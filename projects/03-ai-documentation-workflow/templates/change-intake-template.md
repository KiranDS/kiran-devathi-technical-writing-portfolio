# Change intake template

Copy this template for each proposed customer-facing change.

```yaml
change_id: ""
title: ""
change_type: feature | enhancement | fix | deprecation | security
customer_impact: ""
availability: ""
prerequisites: ""
limitations: ""
source_owner: ""
approval_status: pending
audience: ""
internal_notes: ""
```

## Contributor guidance

- Describe observable customer behavior, not only implementation activity.
- Use exact dates, plan names, role names, and limits.
- Enter `None` only when the owner confirms there are no prerequisites or limitations.
- Keep internal notes separate from publishable facts.
- Do not include customer data, credentials, or secrets.
