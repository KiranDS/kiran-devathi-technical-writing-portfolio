# 5. Quality assurance checklist

Use this checklist for every release-note draft, regardless of whether AI was used.

## Factual accuracy

- [ ] Every factual statement maps to one or more approved source IDs.
- [ ] Product names, feature names, dates, currencies, limits, and plan names match the source.
- [ ] No unsupported performance, security, compatibility, or availability claim appears.
- [ ] No behavior has been inferred from a title or internal note.
- [ ] Pending or rejected changes are excluded.

## Completeness

- [ ] All approved customer-facing changes are represented.
- [ ] Prerequisites are included.
- [ ] Availability and rollout details are included.
- [ ] Known limitations are included.
- [ ] Important migration or action requirements are included where supplied.

## Editorial quality

- [ ] Content is written for the stated audience.
- [ ] Headings and grouping are consistent.
- [ ] Terminology matches the product glossary.
- [ ] Sentences are concise and unambiguous.
- [ ] Acronyms are expanded on first use where appropriate.
- [ ] Links are valid and point to approved destinations.
- [ ] Content is accessible and does not rely on color alone.

## Security and governance

- [ ] No secrets, tokens, personal data, or customer-specific data are present.
- [ ] Internal-only notes are not exposed.
- [ ] Specialist review is complete when required.
- [ ] The AI tool used was approved for the input data classification.
- [ ] Human approval is recorded.

## Release decision

- [ ] Critical findings: 0
- [ ] Major findings: 0
- [ ] Open questions resolved or explicitly excluded from publication
- [ ] Final version and source revision recorded
- [ ] Authorized publisher has approved publication
