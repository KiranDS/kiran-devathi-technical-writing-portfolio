# SupportFlow glossary

| Term | Definition |
|---|---|
| Agent | Support team member who handles customer requests |
| Assignee | User currently responsible for progressing a ticket |
| Backlog | Tickets that remain unresolved at a given point in time |
| Business hours | Configured working periods used by an SLA policy |
| Customer response | Communication intended for the ticket requester |
| First-response time | Time between ticket creation and the first qualifying response |
| Internal note | Ticket information intended for authorised support staff |
| Knowledge article | Reusable content that explains a question, task, or resolution |
| Priority | Relative urgency assigned to a ticket |
| Queue | Filtered view of tickets for a team or user |
| Resolution time | Time measured from ticket creation to the defined resolution event |
| SLA | Service-level agreement; a target for a support activity |
| SLA attainment | Share of eligible tickets that meet the applicable SLA target |
| Team lead | User responsible for team-level workload and ticket oversight |
| Ticket | Record representing a customer support request |
| Workspace | Organisation-specific SupportFlow area containing users, teams, tickets, and settings |

## Usage notes

- Use **ticket** rather than case or incident unless a specific context requires otherwise.
- Use **assignee** for the individual owner and **team** for the responsible group.
- Capitalise UI labels exactly as shown in the illustrative interface: **Inbox**, **Queues**, **Reports**, and **Administration**.
- Use **Resolved** as the status label; use *resolution* for the general concept.
- Define abbreviations at first use in each standalone document.
