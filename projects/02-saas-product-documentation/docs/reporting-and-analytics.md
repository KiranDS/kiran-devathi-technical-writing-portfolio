# Reporting and analytics

**Audience:** Support managers and team leads  
**Product version:** 1.0

## 1. Overview

SupportFlow reporting provides an illustrative view of support workload and service outcomes. Reports help managers identify trends, assess capacity, and investigate service issues.

The metrics and sample values in this guide are examples only. They are not generated by a live system.

## 2. Common metrics

| Metric | Definition | Interpretation |
|---|---|---|
| Tickets created | Number of tickets created in the selected period | Indicates incoming support demand |
| Tickets resolved | Number of tickets moved to Resolved in the selected period | Indicates completed work |
| Open backlog | Tickets not in Resolved status at the reporting time | Indicates outstanding work |
| First-response time | Elapsed time to the first qualifying response | Indicates responsiveness |
| Resolution time | Elapsed time to resolution | Indicates end-to-end handling duration |
| SLA attainment | Share of eligible tickets meeting the defined SLA target | Indicates performance against service commitments |

Metric calculations must be aligned with the organisation's reporting definitions. For example, elapsed time may mean calendar time or business time.

## 3. Open a report

1. Select **Reports**.
2. Choose the report relevant to your question.
3. Set the reporting period.
4. Apply available filters, such as team, priority, or status.
5. Review the metric definitions.
6. Compare the results with the previous period where appropriate.

**Expected result:** The report displays data for the selected period and filters, subject to your access permissions.

## 4. Interpret a sample dashboard

The following fictional sample illustrates how metrics may be presented.

| Metric | Sample value | Commentary |
|---|---:|---|
| Tickets created | 1,240 | Incoming volume for the sample period |
| Tickets resolved | 1,105 | Work resolved during the sample period |
| Open backlog | 315 | Outstanding tickets at the reporting point |
| Median first-response time | 42 minutes | Typical first-response performance |
| SLA attainment | 94.2% | Share of eligible tickets meeting target |

These values are intentionally illustrative and should not be represented as actual SupportFlow performance.

## 5. Ask useful operational questions

Use reports to investigate questions such as:
- Is incoming ticket volume increasing?
- Which queues have the largest backlog?
- Are high-priority tickets receiving timely attention?
- Has median resolution time changed?
- Which ticket categories generate repeat requests?
- Are SLA misses concentrated in a particular team or time period?

A metric alone rarely explains the cause. Review underlying tickets and operational context before drawing conclusions.

## 6. Compare reporting periods

When comparing periods:
1. Use equivalent date ranges where possible.
2. Apply the same filters.
3. Check whether team structures or SLA policies changed.
4. Confirm whether the metric definition remained consistent.
5. Explain material changes in the report commentary.

## 7. Export and data handling

If a real implementation supports report exports, document the supported formats, permission requirements, data fields, and handling restrictions using verified product information.

Do not export or share customer information unless authorised by your organisation.
